# 微信桥接 WSL2 版补充（写给在 Windows 上的朋友）

> 2026-11-07 起草，未在 WSL2 上实测跑通过全流程。用法：先按这份把 WSL2 + Ubuntu + systemd
> 搭好，再按主流程《微信桥接完整流程-2026-11-06.md》第 3 节起在 Ubuntu 里原样走，
> 同时按《微信桥接新增机制交接-2026-11-06.md》把 wx-bot 升到 v0.5.1。
> 三份一起转才完整。本补充不含任何密码、令牌和微信号。

## 0. 一句话结论

wx-bot 不支持 Windows，只支持 Linux 和 macOS（上游安装脚本原话，2026-11-06 已核实）。
在 Windows 上最顺的路是在 WSL2 里装 Ubuntu，然后在 Ubuntu 里把主流程原样跑一遍——
主流程本身不用改，改的是“装 Ubuntu 之前”这几步，和下面列出的几处 WSL 特有的差异。

## 1. 前置要求

- Windows 10 2004+（Build 19041+）或 Windows 11，BIOS/UEFI 里开虚拟化。
- 一个微信号（扫码登录用），先在微信里给 ClawBot 发一条消息（主流程 §7.4，别跳过）。

## 2. 装 WSL2 + Ubuntu（在 PowerShell 里，管理员身份）

```powershell
wsl --install
```

- 默认装 WSL2 + Ubuntu，装完按提示重启，再打开 Ubuntu 创建一个 UNIX 用户名和密码。
- 想指定版本：`wsl --install -d Ubuntu-24.04`；看可选发行版：`wsl --list --online`。
- 装完先更新一次：`sudo apt update && sudo apt upgrade -y`。

## 3. 开 systemd（关键一步，主流程 §5 依赖它）

WSL2 默认不一定用 systemd，没有它 `systemctl` 会报
`System has not been booted with systemd as init system`，服务装不上。
先检查，再决定要不要开：

```bash
ps -p 1 -o comm=    # 是 systemd 就不用往下做；不是才继续
```

不是 systemd 时，在 Ubuntu 里写配置并重启 WSL：

```bash
printf '[boot]\nsystemd=true\n' | sudo tee /etc/wsl.conf
```

```powershell
wsl --shutdown
```

重新打开 Ubuntu，再验证：`ps -p 1 -o comm=` 应为 `systemd`，
`systemctl --version` 能正常输出。之后按主流程 §5 装服务，
把服务文件里的 `<home>` 换成自己的 home 绝对路径，`User=` 换成实际运行用户。

## 4. 再按主流程走（第 3 节起）

- 安装、配置、登录扫码、收发命令（主流程 §3、§4、§6–§8）全部在 Ubuntu 终端里跑，
  不要在 PowerShell / CMD 里跑，`wx-bot` 不在 Windows 的 PATH 里。
- 登录二维码：`wx-bot login muse --qr-png <新文件路径> --timeout 10m` 生成的图在 Ubuntu
  文件系统里，从 Windows 取图走 `\\wsl$\Ubuntu-24.04\home\<用户名>\...`，
  或 `cp` 到 Windows 能访问的目录再发给用户。文件名含二维码 id，不要重命名。
  二维码有效期约 2 分钟，超时重生成（主流程 §7.1）。
- 升级到 v0.5.1、502 时先重启服务重建会话、待发队列的处理，按新增机制交接文档，
  与主流程 §16.2、晚间更新一致。

## 5. WSL2 和我们 Linux 虚拟机的四个不同（别照搬）

1. **WSL 不会随 Windows 开机自启，关掉也会停。** WSL2 在 Windows 启动时不会自动启动，
   关掉最后一个终端或跑 `wsl --shutdown` 后，发行版和里面的 systemd 服务都会停。
   重启电脑后要先打开 Ubuntu（或 `wsl -d Ubuntu-24.04`），`enable` 过的服务才会起来。
   这是我们虚拟机“一直在线”那套没有的步骤，日常用之前先确认服务在跑：
   `sudo systemctl is-active wx-bot`。
2. **`/etc` 不会被清空。** 我们的虚拟机更换会清空 `/etc`，所以主流程 §5.3、§10.4、
   §16.1、§16.3 里那套“服务文件丢失 → 从 home 备份自动恢复”的逻辑，在 WSL2 里
   不适用、不需要照搬。备份 `~/workspace/wx-bot-deploy/wx-bot.service` 仍建议留着，
   但别把看门狗的换机恢复逻辑原样抄过去。
3. **`sudo -n` 不一定能直接用。** 主流程里写的是无密码 sudo（`sudo -n systemctl ...`）。
   WSL 默认用户一般是有密码的 sudo，没有配过无密码 sudo 就把命令里的 `-n` 去掉，
   按提示输密码；或者按自己的习惯配好无密码 sudo 再用原文。
4. **定时任务和 hook 按朋友自己的 Muse 落。** 主流程 §10（唤醒 hook）、§13
   （动态同步、Tibo 监测、看门狗定时任务）是按我们的 Muse 运行时写的。
   朋友那边 Muse 怎么跑、定时任务放哪，就按他那边的实际运行方式落，
   能跑的照搬，不能跑的不要硬套——这部分在 WSL2 上未验证。

## 6. 排障速查（WSL 特有）

| 现象 | 先查 |
|---|---|
| `systemctl` 报没有用 systemd 启动 | `ps -p 1 -o comm=`，回第 3 节开 systemd 后 `wsl --shutdown` 重启 |
| 重启电脑后微信没反应 | Ubuntu 有没有打开；`sudo systemctl is-active wx-bot`；`wx-bot status` |
| `send` 返回 502 | 先看新增机制交接：重启服务重建会话再试；不是本地配错，见主流程 §16.2 |
| 登录被风控拦 | 别连续扫码硬撞，等几小时、换出口路线再试（主流程 §7.2） |
